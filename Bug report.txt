Bug Title 8: Missing Status Cascade on Policy Deactivation Leaves Child Employee Assignments Active (Cascade Desynchronization Defect)

method - PATCH & GET
url (Deactivate Parent) - https://uatmcdphcmplatform.omfysgroup.com/api/attendance/late-early-policies/138/status?status=N
url (Inspect State)     - https://uatmcdphcmplatform.omfysgroup.com/api/attendance/late-early-policies/getById/138

Explanation:
When an admin deactivates a Late/Early Policy (PATCH status?status=N), the backend only updates the parent policy record to isActive = 'N' and fails to cascade the deactivation to child employee assignments and deduction priorities. As a result, employee assignments remain active ('Y') under a deactivated policy, causing automated payroll and attendance deduction batch jobs to incorrectly penalize employees under a policy that HR had disabled.

Bug Title 9: Missing Foreign Active-State Validation on Leave Type Allows Creation of Corrupted Policies Linked to Deactivated Leaves (UI Rendering & Update Failure)

method - POST 
url - https://uatmcdphcmplatform.omfysgroup.com/api/attendance/late-early-policies/create

UI Navigation Path:
1. Go to Attendance Management -> Late / Early Policy list table.
2. Search for Template Code 'LEP00175' (or 'Deactivated Leave Gating Test 2038').
3. Click on the Edit (pencil icon) button to open the 'Edit Late/Early Policy Template' modal.
4. Observe the 'Leave Type for Deduction *' field: It renders as BLANK ('Select leave type') because the frontend dropdown hides inactive leaves (OD), failing to bind the backend's leaveTypeId: 7.
5. Attempting to click 'Update' blocks the user with a mandatory field validation error, rendering the policy permanently un-editable from the UI.

Explanation:
In the Leave Master API (/admin/leaves/getleavestypes), Leave Type ID 7 ('OD') is marked as deactivated (is_active = 'N'). However, the Late/Early Policy creation endpoint only verifies if leaveTypeId exists in the database table and fails to check if is_active == 'Y'. Consequently, the API allows creating an active attendance policy bound to a disabled leave type. When HR opens this template in the UI, the frontend dropdown fails to match the disabled leave type and displays blank, causing corrupted state and blocking updates.
